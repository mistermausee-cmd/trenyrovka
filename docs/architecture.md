# Архитектура Trenyrovka

## Цель

Однопользовательский, mobile-first трекер 12-недельной домашней программы. Приложение само определяет дату и время в `Europe/Oslo`, показывает тренировку или восстановительный день, ведёт пользователя по одному упражнению за раз и сохраняет фактические подходы, самочувствие, замеры и заметки для последующего анализа тренером.

## Пользовательские сценарии

1. **Первый запуск** — ввод одноразового setup-токена, создание пароля, выбор даты старта и доступного оборудования.
2. **Сегодня** — локальная дата/время Осло, фаза программы, следующая тренировка, недельный прогресс и одна главная кнопка.
3. **Режим тренировки** — короткая проверка готовности, разминка, затем одно упражнение на экране: цель, техника, схема движения, короткое видео, ввод повторов/нагрузки/RIR, таймер отдыха, пропуск только с причиной.
4. **Завершение** — длительность, субъективная нагрузка, боль, заметка и сводка прогресса.
5. **Журнал** — календарь тренировок, подробности каждого подхода и личные рекорды.
6. **Прогресс** — вес, талия и другие замеры, соблюдение плана, тренировочный объём и динамика упражнений.
7. **Экспорт для тренера** — JSON и читаемый Markdown без пароля, с настройками, замерами, тренировками и подходами.
8. **Настройки** — дни занятий, дата старта, оборудование, часовой пояс, смена пароля и резервная копия.

## Программа

- 3 полнотелые тренировки в неделю с чередованием `A/B`.
- Недели 1–2: 2 рабочих подхода и примерно 3 повтора в запасе.
- Недели 3–8: 3 подхода и 2–3 повтора в запасе.
- Недели 9–12: 3 подхода и 1–2 повтора в запасе; необязательный дополнительный подход плеч/спины только при хорошем восстановлении.
- Пропущенный день не удаляет тренировку: приложение предлагает выполнить следующий незавершённый шаблон сегодня.
- Без резинок используются рюкзак и вес тела; после отметки оборудования автоматически появляются безопасные замены с резинками.

## Техническая схема

```text
Browser / PWA
    |
    | HTTPS (или HTTP только для локального IP)
    v
Caddy :80/:443
    |
    v
Fastify :3000
    |-- /api/*       JSON API
    |-- /*           собранный React SPA
    v
SQLite /data/trenyrovka.db (WAL)
```

- **Frontend:** React 19, TypeScript, Vite 8, React Router, Recharts, Lucide.
- **Backend:** Fastify 5, TypeScript, Zod, better-sqlite3.
- **Deployment:** Docker Compose; один контейнер приложения и Caddy; bind-mounted data/backups.
- **Timezone:** расчёт календаря на сервере через IANA `Europe/Oslo`; браузер получает уже определённую локальную дату и дополнительно показывает живые часы через `Intl.DateTimeFormat`.

## Данные

### `users`
Единственный пользователь: хэш пароля (scrypt), дата создания и изменения.

### `auth_sessions`
Хэш случайного session-токена, CSRF-токен, срок действия и дата последнего использования. Сырой session-токен существует только в HttpOnly cookie.

### `settings`
Дата старта, тренировочные дни, оборудование, часовой пояс и предпочтения интерфейса.

### `workout_sessions`
Шаблон A/B, запланированная дата, фактические начало/конец, статус, сон, готовность, общая нагрузка, боль и заметки.

### `set_logs`
Снимок упражнения и цели на момент занятия, номер подхода, повторения/секунды, нагрузка, RIR, статус и время выполнения.

### `measurements`
Дата, масса, талия, грудь, плечо, бедро, сон и заметка. Все поля, кроме даты, необязательны.

### `activity_events`
Минимальный журнал значимых действий (старт/завершение/пропуск/изменение плана), без IP-адресов и сторонней аналитики.

## Безопасность и приватность

- Первый пользователь создаётся только при предъявлении случайного setup-токена, созданного установщиком.
- Пароль хэшируется `scrypt` с уникальной солью; пароль и setup-токен никогда не записываются в журнал.
- Сессии: случайные 256-битные токены, в БД хранится только SHA-256 хэш; cookies `HttpOnly`, `SameSite=Strict`, `Secure` при HTTPS.
- Все изменяющие запросы требуют CSRF-токен и same-origin проверку.
- Ограничение частоты запросов для setup/login; единообразные сообщения об ошибках.
- Helmet/CSP; видеокадры разрешены только с `youtube-nocookie.com`; внешней аналитики, рекламных SDK и трекеров нет.
- Валидация и ограничения длины на сервере; параметризованные SQLite statements.
- Контейнер запускается непривилегированным пользователем, файловая система read-only кроме `/data` и `/backups`.
- Экспорт не содержит хэши пароля, session-токены, setup-токен или внутренние события авторизации.

## Резервное копирование

Приложение создаёт согласованную SQLite-копию через API `better-sqlite3.backup()`. Установщик добавляет ежедневный systemd timer, хранящий семь последних копий в `/opt/trenyrovka/backups`. В интерфейсе также доступны полный JSON и Markdown для тренера.

## Развёртывание

`deploy/install.sh`:

1. Проверяет Ubuntu и права root.
2. Устанавливает Docker Engine/Compose из официального репозитория Docker, если их нет.
3. Получает выбранную ветку GitHub (с поддержкой приватного репозитория через токен).
4. Спрашивает домен или IP, создаёт случайные секреты и `.env` с правами `0600`.
5. Собирает и запускает Compose, проверяет health endpoint.
6. Устанавливает timer резервного копирования и выводит URL, setup-токен и подсказку по Azure NSG.

Для домена Caddy автоматически получает TLS-сертификат. Для IP приложение запускается по HTTP и явно предупреждает, что пароль нельзя безопасно передавать через публичный интернет без HTTPS; предпочтительный вариант — домен или доступ через VPN/Tailscale.
